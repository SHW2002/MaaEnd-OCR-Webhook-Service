# 数据集录制与评估

[English](DATASETS.md) | 简体中文

## 录制

打开目标窗口，在 GUI 的 **开发选项 → 录制数据集** 选择保存目录、采集间隔与场景说明，然后开始录制。目标窗口标题来自 **配置**。

默认目标标题为 `MaaEnd v`，默认忽略大小写；**窗口标题区分大小写** 同时作用于实时识别和录制，与 **锚点区分大小写** 独立。

默认保存目录为可执行文件所在目录下的 `records\`；目录框显示相对于程序目录的路径，输入的相对路径也以程序目录解析。每次录制创建 `session-yyyyMMdd-HHmmss` 会话子目录，例如 `session-20261010-121022`；同秒录制重名时添加 `-2` 等数字后缀，目录名不含随机编号。也可以通过 **浏览** 更换保存位置。

点击 **停止** 后留在录制页，选择 **保存录制** 或 **删除录制**。录制期间先写入保存目录下的 `.pending-session-*` 临时会话；保存会将其移为正式 `session-*` 目录并打开评估页，删除只移除本次临时会话。处理前不能开始下一次录制；没有可用帧时只能删除。关闭主窗口时若还有待处理录制，可以保存、删除或取消关闭。

录制器使用与正式运行相同的 `ScreenCapture`：优先 `PrintWindow`，失败后尝试 DWM 缩略图。它只采集配置中的目标窗口，保存完整目标窗口的原尺寸无损 PNG，不录制全屏，不执行 OCR，也不依赖锚点识别成功。此录制格式可在应用内播放，不是 MP4，不需要 FFmpeg 或额外录屏软件。

**采集间隔（毫秒）** 是相邻两次完整窗口截图的目标时间间隔，默认 100ms（约 10 帧/秒），可设为 33–60000ms。数值越小，采集越密集、存储占用越大；数值越大，越容易遗漏短暂出现的画面。此参数控制录制采集，不是 OCR 识别间隔。

调度以单调时钟为准；处理超过间隔时跳过过期时段，不挤压补录。实际时间戳、采集失败、跳过的采样时段都记录在清单中。它不能保证硬实时帧率。

保存后的会话目录：

```text
session-20261010-121022/
  dataset.json
  annotations.json
  frames/
    000000.png
    000001.png
  reports/
    评估时间-唯一编号/
      report.json
      report.md
```

清单包含会话 ID、采集起止时间、操作系统与 .NET 版本、可用 OCR 语言、识别配置快照、场景、每帧窗口标题/尺寸/DPI、采集方式、采集耗时、UTC 时间、相对时间戳和 SHA-256。配置快照不保存实际 Webhook 地址与请求体。

相同画面不去重，因为真实连续帧是验证跨帧去重的输入。每帧采集后更新清单，正常停止会补写结束时间；异常退出不会自动删除临时会话，已经写入的帧仍可从其中的 `dataset.json` 打开。

建议录制多个会话，覆盖 DPI/缩放、窗口宽度、不同日志颜色、长行换行、空日志、单行、快速新增、滚动过渡与任务结束。调整窗口尺寸时共享识别流程会重新定位锚点。改变布局但保持尺寸时，仍沿用已定位的区域，与正式运行一致。

## 浏览与标注

在 **开发选项 → 评估数据集 → 浏览** 选择 `dataset.json`，也可在路径框填入会话目录后点击 **载入**。浏览默认进入程序旁的 `records\`；已有路径时进入对应目录。**打开目录** 在资源管理器中打开当前路径对应的文件夹。路径为空或指向录制根目录时，**载入** 会打开数据集选择对话框。

载入时自动读取会话中的 `annotations.json`，定位首个有文字真值的帧，并显示有文字和已确认的帧数。每帧显示真值状态，已确认的空日志也会明确注明。外部更新标注后可点击 **重载标注** 刷新当前帧；若有未保存编辑，会先保存。保存当前帧会保留磁盘上其它帧与事件标注。

- 使用播放、滑块、上一帧、下一帧查看画面；**原尺寸** 可检查细小文字。
- 表格显示当前帧的标注。**标注变化** 下拉框和 **上一组 / 下一组** 跳过文字真值相同的连续帧。**全部标注** 汇总整个会话的文字，按日志时间与正文去重展示，包含尚未确认的标注；双击或点击 **定位帧** 可跳到对应画面，不会改变真值确认状态。
- 表格只标注日志区域中的逻辑日志行，分别填写时间与完整正文。按画面顺序填写；换行延续的同一条日志仍是一行。
- **OCR 草稿** 使用共享 OCR 流程填入预测，但不会确认真值。必须人工逐项核对，修正后勾选 **真值已确认**。
- 真值中保留可见文字，不应照抄识别器的错误；无法判定的帧保持未确认。
- 空日志可以删除所有表格行后确认，避免遗漏误报评估。**锚点可见** 表示完整窗口中确实出现配置的锚点。
- 可修改场景分类；切换帧或关闭主窗口会保存修改，也可点击 **保存标注**。

帧标注与会话事件标注分开：帧标注衡量文字识别；事件标注衡量输出、遗漏与重复。

通过 **事件真值** 标注整个会话应该输出的真实事件，包含日志时间、正文、首次出现的相对毫秒数。相同正文在不同时间出现属于不同事件。可以从已确认帧生成草稿，但要根据完整录制补齐遗漏，并人工确认整个会话后才计算事件指标。

## 评估模式与共用代码

点击 **开始评估** 后，只运行当前分支正式方案。Master 沿用原有滚动 OCR：8 倍放大、彩色对比度增强与锐化的单候选识别。正式运行与评估共用 `RollingOcrRecognizer` 入口；单候选没有规则评分，报告中的评分字段为 `null`。

评估与正式运行共用 `FrameRecognitionPipeline`，包含全窗口锚点定位（4 倍高对比度）、裁剪、OCR 引擎、分块、行重组、时间正文解析，以及 `RollingOcrOutputFilter` 的清洗、过滤和历史去重。评估只将窗口输入替换为录制帧，输出替换为本地报告，不发送 Webhook。

- **线程** 可设为 1–8，默认按 CPU 数量选择、最多 4。按录制时间平均切成连续片段，每个线程评估一段，不追求帧数和工作负载相等；空片段不启动线程。所有结果按时间顺序统一过滤、拒绝不稳定帧和跨帧去重，跨段重复日志不会重复输出。
- 默认勾选 **按正式频率采样**：每段内按上轮定位、裁剪与 OCR 实测耗时，加录制配置中的等待时间，选取下一张时间戳不早于该时刻的帧。跳过的图片不读取或执行 OCR，无需等待真实录制时长。定位失败使用重试间隔，各段分别遵守重试上限；正文指标仅计算实际采到的已确认帧。
- 每段首帧独立采样并重新定位窗口，分段边界及 CPU 争用可能改变采样画面；统一过滤在识别完后执行，其耗时不参与段内下一帧调度。设为 **1 个线程** 可以连续回放整个会话，并用于单独运行性能测量。
- 取消 **按正式频率采样** 才进入 **逐帧模式**：所有帧均执行当前方案，可比较不同线程数对相同输入的处理结果，耗时更长。线程选项独立于采样选项。

正式运行现在也在拒绝帧后正常等待，修正旧代码跳过等待而立即重试的行为。两种模式都使用相同的共享等待规则。

每个实际识别样本在解码前检查 SHA-256，损坏或修改的样本会导致评估失败；未采样帧不做图片内容校验。进度汇总所有线程的样本数、录制时间覆盖进度及结束片段数；停止或任一片段失败都会取消并等待所有线程结束。取消时不输出完整报告，已确认标注仍保留。

## 指标口径

| 指标 | 计算口径 |
| --- | --- |
| CER | 正文按顺序连接（含换行），字符编辑距离 / 真值字符数；漏字、多字和错字均计入，可超过 100% |
| 正文整行正确率 | 按正文序列对齐后正文完全正确的真值行数 / 真值行数；忽略时间，漏行算错 |
| 整行正确率 | 时间与正文均正确的真值行数 / 真值行数；漏行算错 |
| 时间准确率 | 按正文序列对齐后时间完全正确的行数 / 真值行数 |
| 锚点成功率 | 人工确认存在锚点的已处理帧中，共享流程成功获得日志区域的比例，包含缓存定位 |
| 输出精确率 P | 正确事件数 / 全部输出事件数 |
| 输出召回率 R | 正确事件数 / 应输出的真值事件数 |
| F1 | 2 × 正确事件数 /（输出事件数 + 真值事件数） |
| 事件延迟 | 识别完成的回放时间 − 真值首次出现时间，报告中位数 |
| 耗时 | 完整共享流程耗时的中位数与 P95，包含所需的锚点识别、裁剪、全部候选、评分与过滤 |

事件按时间和正文严格一对一匹配，而且必须在采样帧时已经出现；重复输出计错报。OCR 分数不是准确率。未确认帧不参与准确度；事件真值未确认时不计算 P/R/F1。分母为零显示 `—`，不冒充 100%。报告同时列出总帧数、人工确认帧数、处理帧数和参与准确度计算的帧数。

严格指标保留原文字；统一排版指标仅做 Unicode FormKC 与空白归一，不自动修正错字。耗时不包含磁盘读取、PNG 录制或网络推送，回放延迟也不包含网络耗时。结果受当前机器与 Windows OCR 语言包影响。录制帧间短暂出现的日志仍可能缺失。

`report.json` 包含线程设置（`RequestedWorkers`）、实际片段数（`WorkerCount`）、执行方式（`ExecutionMode`）、评估总耗时（`WallMilliseconds`，不含报告写入）。单一 `Result` 包含片段范围与耗时、每帧输出、候选原文、评分、流程耗时、裁剪坐标和错误。`report.md` 是可阅读的汇总，并说明分段及并行耗时口径。并行耗时受 CPU 争用影响，回放事件延迟不代表并行评估墙钟延迟。

调参集和最终评测集按会话分开，避免同一段录制的相邻帧分别出现在两边。当前工具评估所选会话，不自动划分训练/测试集，也不导入其他录屏软件的视频文件。
